# Issue #19 approved design: dedicated counters

29 November 2026 (Asia/Bangkok). The user explicitly selected **design 2** after the Phase 0 contradictions were reported. This decision supersedes conflicting F-09 statements in the four Sprint 2 contracts; the original shared-counter proposal remains historical text. The user also authorized local commits between phases and continuation through Phase 7, with **no push**.

Counter R (code `R`, name `Counter R`) belongs only to existing Queue R; Counter S (`S`, `Counter S`) belongs only to existing Queue S. Both assigned operators can use either counter. Preserve A/R, A/S, B/R and B/S, the queue-level one-CALLED-or-SERVING index, and one active service per counter. R and S operate independently. No ownership, extra queue, dynamic administration, unified dashboard or ETA is introduced by #19.

`service_counters(id UUID, code UNIQUE, name, queue_id)` references queues. `queue_entries.counter_id` is nullable and has a composite foreign key `(counter_id, queue_id)` to the counter. CALLED/SERVING requires a counter; WAITING/CANCELLED must have none. COMPLETED/NO_SHOW retain their historical counter, while pre-migration terminal rows may remain null. Occupancy is derived only from CALLED/SERVING; a partial unique index on counter_id covers that combined set. Queue numbering, customer uniqueness and restrictive deletion remain intact. No independent occupancy flag or eligibility join table is needed. Audit actor/time attribution is unchanged; historical counter identity is available through its retained entry association.

Migration is one transaction: preflight supported active queues and required called/serving timestamps, reuse R/S, provision missing compatible counters, backfill active entries, validate coverage, then add constraints. Preserve all existing records and timestamps, sequence values, sessions, assignments and events. Incompatible counter configuration or invalid active data aborts without partial changes. Keep both earlier migrations unchanged. Old writers cannot create active entries without a counter after migration, so stop writers and exclude mixed-version traffic until a compatible application is running. No deployment is authorized.

## API and UI contract for #19

Existing routes and privacy boundaries remain. `GET /operator/queues/:queueId/desk` adds `activeEntries` (zero or one operational entry) and `counter` (null for an unprovisioned queue, otherwise `{id,code,name,queueId,status,occupant}`). Status is `AVAILABLE` or `OCCUPIED`, and occupant is null or `{entryId,displayNumber,status}`. These are operator-only fields. Existing scalar fields and `asOf` remain. The dashboard and public active-entry-list proposal belongs to later integration; the existing four-field public board remains unchanged in this design.

Call accepts legacy `{}`/absent JSON body, optional `counterId`, and optional `expectedEntryId` only together with counterId. Validate object shape, unknown properties and UUIDs with 422. Resolve the queue's counter when omitted. Nonexistent/foreign counter returns 403 COUNTER_ACCESS_DENIED; busy queue/counter returns 409 SERVICE_SLOT_BUSY; non-OPEN remains QUEUE_NOT_OPEN. Missing preview head yields QUEUE_HEAD_CHANGED, otherwise empty yields QUEUE_EMPTY. All denials leave state unchanged. Authorization precedes domain state disclosure. Call locks queue then counter, rechecks occupancy/FIFO after locks, persists counter/status/time/event atomically. Start validates and retains the association. Completion/no-show changes status and retains counterId in storage and operator responses; occupancy becomes available. No-show retains the inclusive 300-second manual threshold. Cancel is WAITING-only and cannot free another entry's reservation. An active entry with inconsistent linkage is an internal invariant failure, never a silent reassignment.

The existing queue selector stays. Display counter name/code, queue, AVAILABLE/OCCUPIED and the active reservation number/state from the desk snapshot. New UI sends the displayed counter and FIFO head with Call Next. Disable invalid calls, prevent duplicate submissions, and refresh authoritative state after success, transport failure or conflict. No auto-replay. Show contextual busy/changed-head feedback. Existing scalar-only mocks/legacy responses remain supported. No-show confirmation includes counter context. Keep responsive/keyboard behavior.
