## Execution setup and evidence

Every case below is **planned, execution pending**. Use isolated PostgreSQL with production-equivalent migrations and synthetic A/B operators assigned to R/S, an R-only operator, an unassigned operator and distinct customers. Use the proposed configuration of two shared counters in total, C1 and C2, both eligible for R and S, pending confirmation. Reset DB fixtures per case and use explicit sequence/timestamps. For simultaneous API requests use separate sessions/connections and a test barrier, asserting persisted state and events after both requests settle. For ordered assertion capture lock acquisition via a first-writer barrier and assert event/assignment order independently of response order. Inject the lifecycle action clock (and ETA read clock) for boundaries. Fixtures and test code are implementation work.

P0 covers release-blocking integrity, privacy and core workflows. P1 covers UI and calculation refinements. For #21 record SHA, environment, migration IDs, commands, exact results and evidence links. Run baseline suites with revised expectations from [Part F](specification.md#part-f--requirements-traceability-and-regression). Historical Lab 7 results are referenced in [Part D](specification.md#part-d--change-and-approval-record).
